# Frontier AI Agent Skill Benchmark Suite

`skill-benchmarks` runs skill-and-scenario benchmark executions through a command-line interface. Its normal mode is deterministic fake execution, so a checkout is usable without provider credentials or a network connection.

## Quickstart

Install dependencies, then run the included fake trajectory:

```bash
bun install
bun run cli -- run \
  --mock \
  --scenario git-worktrees \
  --skill using-git-worktrees \
  --model claude-3-7-sonnet \
  --output-dir .benchmarks
```

Fake mode is the default. `--mock` makes that selection explicit. The fake provider performs no provider request, uses a disposable workspace below the output root, and writes a deterministic tool trajectory. A completed fake execution is not a scored benchmark pass: score and pass status remain unevaluated until evaluation evidence is produced.

## Live execution

Use `--live` only when you intend to contact a provider. It requires a nonblank credential for the selected provider before any provider request.

```bash
ANTHROPIC_API_KEY="replace-with-a-real-key" bun run cli -- run \
  --live \
  --scenario git-worktrees \
  --skill using-git-worktrees \
  --model claude-3-7-sonnet \
  --output-dir .benchmarks
```

`SKILL_BENCHMARKS_USE_MOCK=true` selects fake mode; `SKILL_BENCHMARKS_USE_MOCK=false` selects live mode. `--mock` and `--live` cannot be used together. See [configuration](docs/usage-guide/getting-started/configuration.md) for provider-specific credential names.

## Runtime artifacts

The default runtime root is `.benchmarks/`; `--output-dir` or `SKILL_BENCHMARKS_OUTPUT_DIR` can select another root. Runtime output is ignored by Git. Checked-in files in `data/` are demonstrations, not results generated by the CLI.

```text
.benchmarks/
├── db/benchmarks.sqlite
├── runs/<run-id>/
│   ├── manifest.json
│   ├── result.json
│   └── workspace/
└── sweeps/<sweep-id>/checkpoint.json
```

`.benchmarks/exports/` is optional and reserved for files written by `report --output`; it is not generated run evidence. Use the generated database explicitly when exporting a report:

```bash
bun run cli -- report \
  --db .benchmarks/db/benchmarks.sqlite \
  --format markdown \
  --output .benchmarks/exports/leaderboard.md
```

The full artifact contract, including every per-run path, is in the [configuration guide](docs/usage-guide/getting-started/configuration.md). The [single-trial guide](docs/usage-guide/running-benchmarks/single-trial.md) explains how to inspect a run, and the [CLI reference](docs/usage-guide/cli-reference/commands.md) covers runnable commands.

## Local verification

```bash
bun run typecheck
bun run src/scripts/quality-gate.ts
```

CI runs one deterministic no-key operational diagnostic with Bun 1.3.14. Its `simulated-diagnostic-<sha>` artifact proves installed-command execution, workspace isolation, event persistence, terminal reconciliation, database persistence, and diagnostic report empty-state health. It does not publish benchmark results, rankings, or regression decisions.

Reproduce the diagnostic locally with a temporary bundle:

```bash
bundle="$(mktemp -d)/skill-benchmarks-simulated-diagnostic"
runtime="$bundle/runtime"
mkdir -p "$bundle/logs"
env -u ANTHROPIC_API_KEY -u OPENAI_API_KEY -u GEMINI_API_KEY -u GOOGLE_API_KEY \
  SKILL_BENCHMARKS_USE_MOCK=true \
  bun bin/skill-benchmarks run \
    --mock \
    --scenario git-worktrees \
    --skill tdd \
    --model gpt-4o \
    --output-dir "$runtime" 2>&1 | tee "$bundle/logs/run.log"
bun bin/skill-benchmarks report \
  --db "$runtime/db/benchmarks.sqlite" \
  --format json \
  --output "$runtime/exports/diagnostic-report.json"
bun run verify:ci-diagnostic -- "$bundle"
```
